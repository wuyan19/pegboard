# Pegboard 需求文档

## 1. 背景

AI 能低成本生成 HTML/JS 小工具，但浏览器缺少本地能力：跨域请求、文件读写、持久化存储、内网访问。需要一个宿主程序补齐这些能力，让 AI 生成的工具开箱即用。

## 2. 目标

- 提供一个宿主，托管 AI 生成的 HTML 应用，使其无需构建即可运行。
- 宿主提供浏览器不具备的能力，作为稳定 SDK 供应用调用。
- 支持自己和同事通过 URL 访问。
- 应用之间相互隔离，宿主不承担业务语义。

## 3. 用户

- 主要：自己。
- 次要：同事（通过内网 URL 访问）。

信任模型：内部工具，威胁模型以“防误操作”为主，非“防恶意用户”。

## 4. 核心原则

- 宿主只做浏览器做不到的事。
- 宿主提供能力与边界；应用拥有语义与用户。
- 应用之间强制隔离；应用内部组织由应用自行决定。
- 需求稳定优先于功能丰富。

## 5. 场景

| 场景 | 关键能力 |
|---|---|
| 多人 Ollama Chat，会话隔离 | 流式代理、存储原语、可选调用者标识 |
| GLM 额度查询 | 跨域代理、密钥存储 |
| 局域网文件共享 | 文件读写、签名分享链接 |

## 6. 功能需求

### 6.1 静态托管
- 托管 AI 生成的应用，支持单文件 HTML 与前端框架编译产物。
- 支持 SPA 回退、正确 MIME、Range、缓存。
- 应用通过 URL 直接访问。

### 6.2 存储能力
- 提供 KV 原语与文件（Blob）原语。
- 按应用强制隔离。
- 提供文件签名访问，用于临时分享。
- 应用内部命名空间由应用决定。

### 6.3 网络能力
- 提供跨域 HTTP 代理，语义对齐浏览器 fetch。
- 提供 WebSocket 代理。
- 提供资源代理地址，用于图片、字体、样式。
- 支持流式响应（SSE、分块）。
- 提供全局 fetch 兜底，使未显式使用 SDK 的跨域请求也能工作。

### 6.4 调用者标识（可选）
- 提供不透明的调用者标识，允许为空。
- 标识来源可配置：固定值、反向代理注入、手工 token。
- 宿主不提供登录、用户表、角色。

### 6.5 治理
- 应用通过清单声明的权限与限额生效。
- 记录访问与错误日志。
- 提供资源限额：存储、文件、请求频率。

### 6.6 管理
- 提供 Web 管理页：应用列表、安装/卸载、权限查看、日志。

## 7. 非功能需求

- **安全**：默认拒绝内网、本机、云元数据地址；重定向逐跳校验；代理请求与响应头双向清理。应用密钥由应用自行管理（存于自身 KV），宿主不提供加密存储，保密依赖内网边界。
- **隔离**：应用间数据与文件不可互访。
- **性能**：代理不缓冲流式响应；大文件流式落盘。
- **可移植**：单二进制，跨平台。
- **可维护**：宿主能力面稳定，新增能力不破坏既有应用。

## 8. 边界（明确不做）

- 不做系统级代理、不做 HTTPS 中间人。
- 不做登录、用户表、角色、会话管理。
- 不做应用商店、发布、审核。
- 不做业务数据模型、分享授权决策、数据 schema。
- 不做跨应用查询。

## 9. 验收标准

- 三个场景应用无需修改 CORS 代码即可运行。
- 应用间数据互不可见。
- 未声明权限的目标被拒绝，且返回可读错误。
- 流式响应首字节延迟与直连相当。
- 同事通过 URL 可访问静态应用。

## 10. 原待定项决议

- 调用者标识默认部署方式：v1 固定值模式（`identity.kind = "fixed"`），token / 反代注入模式后置（见 API 契约 §6）。
- 文件配额与清理策略：已定，见数据模型 §8、§9。
- 管理页鉴权：由部署配置决定（API 契约 §8）；v1 本地模式无鉴权。
