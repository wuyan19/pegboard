## 修复：大文件上传报 INVALID_REQUEST（M7 交付后用户反馈）

**根因**：axum 对请求体有默认 2MB 上限（`DefaultBodyLimit`，`Multipart` extractor 受其约束）。超过 2MB 的文件在 `next_field()` 处报 `LengthLimitError`，而 handler 把所有 multipart 错误一律映射为 `INVALID_REQUEST` 400——错误码也错了（字节类超限应为 `LIMIT_EXCEEDED` 413）。e2e 用 27 字节 buffer，未暴露。

**修复**
- POST /api/files 路由 `DefaultBodyLimit::disable()`：配额本就在流式读取中逐块校验（超 `file_bytes` 即断，返回 413 + detail），解除默认上限后大文件才能走到该检查。
- multipart 错误按 `MultipartError::status()` 映射：413 → `LIMIT_EXCEEDED`，其余 → `INVALID_REQUEST`。
- lan-share 页面错误提示带出 `message`（原来只显示 code）。

**回归锁定**：files 契约新增 3MB 上传+下载内容校验；M7 Playwright 场景新增 3MB `big.bin` 上传与内容完整性断言；真实服务器 curl 冒烟 3MB → 200。

## 修复：CLI 不支持 -h/--help（用户反馈）

**根因**：与 clap std 同源的冻结清单缺陷——`default-features = false` 只显式开了 `std`，clap 的 `help` 特性（注册 -h/--help、渲染帮助/用法文本）被关闭，`--help` 落到 "unexpected argument found"。
