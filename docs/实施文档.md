# IMPLEMENTATION.md

## 里程碑

| 里程碑 | 交付物 | 验收 |
|---|---|---|
| M0 | workspace + 空 crate + CI | `cargo check` 通过 |
| M1 | `pegboard-cli --check` | 扫描 apps、解析清单、打印列表 |
| M2 | 静态托管可访问 | 浏览器打开 `/apps/<id>/index.html` |
| M3 | `host.store` 通 | 应用读写 KV |
| M4 | `host.fetch` 通 | 跨域请求成功，越权被拒 |
| M5 | `host.files` + 签名通 | 上传、下载、签名分享 |
| M6 | `host.connectWS` 通 | WS 双向通信 |
| M7 | 三个场景端到端 | Ollama / GLM / 局域网共享可运行 |

每个里程碑对应一个发布点；M7 为首版。

## 验收命令

```bash
# 全量
cargo test --workspace

# 单模块
cargo test -p pegboard-core config
cargo test -p pegboard-core app
cargo test -p pegboard-core store
cargo test -p pegboard-core files
cargo test -p pegboard-core guard
cargo test -p pegboard-core proxy
cargo test -p pegboard-core identity
cargo test -p pegboard-core audit

# 契约
cargo test -p pegboard-server --test contract

# 场景
cargo test -p pegboard-cli --test scenarios

# 依赖方向
./scripts/check-deps.sh

# 自检
cargo run -p pegboard-cli -- --check
```

## 并行边界

- M1 与 M2 可并行（前者 core，后者 server 骨架）。
- M3 依赖 M1 + M2。
- M4 依赖 M3（guard 权限部分）。
- M5 与 M6 可并行。
- M7 依赖全部。

同一里程碑内，任务按编号串行；跨里程碑看依赖。

## 完成定义

- 代码合并、CI 绿。
- 单元 + 集成测试覆盖该任务范围。
- 契约测试同步更新。
- 无 `unwrap`（非测试）、无 `println!`、无反向依赖。
- 文档若变更，同步更新对应设计文档。
