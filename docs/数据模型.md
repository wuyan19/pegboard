# Pegboard 数据模型与存储详细设计

## 1. 存储根

```
<data_root>/
  config.toml                  宿主配置（只读加载）
  host.db                      宿主元数据
  apps/
    <app_id>/
      app.db                   KV + 文件元数据
      files/
        <ab>/<cd>/<id>         文件内容，按哈希前缀分片
  logs/
    audit.log                  结构化审计日志
  tmp/                         上传暂存，写入原子化用
```

原则：
- 应用数据全部在 `apps/<app_id>/` 下，物理隔离。
- 宿主元数据与业务数据分离。
- 临时文件与最终存储同盘，保证 rename 原子。

## 2. 标识

- `app_id`：清单中声明，`[a-z0-9_-]{1,64}`，目录名。
- `file_id`：宿主生成，ULID 或 UUIDv7，单调、可排序、全局唯一。
- `subject`：不透明字符串，可为空；仅用于审计与签名归属记录，不做用户模型。
- 签名 `token`：随机 256 位，URL 安全编码。

## 3. KV 模型

存于 `app.db`：

```sql
CREATE TABLE kv (
  key        TEXT PRIMARY KEY,
  value      BLOB NOT NULL,      -- JSON 序列化
  size       INTEGER NOT NULL,   -- 字节数，用于配额
  updated_at INTEGER NOT NULL
);
CREATE INDEX idx_kv_updated ON kv(updated_at);
```

- `key`：应用定义，URL 解码后原样存储，最长由限额控制。
- `value`：JSON，宿主不解释。
- `size`：写入时计算，配额与清理依据。
- 键空间语义归应用；宿主只保证前缀查询。

## 4. 文件模型

### 4.1 元数据

存于 `app.db`：

```sql
CREATE TABLE files (
  id         TEXT PRIMARY KEY,     -- ULID
  name       TEXT NOT NULL,        -- 原始文件名
  mime       TEXT NOT NULL,
  size       INTEGER NOT NULL,
  sha256     TEXT NOT NULL,        -- 内容哈希
  path       TEXT NOT NULL,        -- 相对 files/ 的路径
  created_at INTEGER NOT NULL,
  refcount   INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_files_created ON files(created_at);
CREATE INDEX idx_files_sha     ON files(sha256);
```

### 4.2 内容

- 路径：`files/<sha256[0:2]>/<sha256[2:4]>/<file_id>`。
- 分片避免单目录膨胀。
- 相同 `sha256` 可去重：同内容只存一份，元数据各自 `refcount`。
- 内容写入流程：上传 → 暂存 `tmp/` → 计算 sha256 → 目标已存在则复用，否则 rename 落位 → 元数据入库。
- 全程流式，不整文件入内存。

### 4.3 一致性

- 内容先落位，元数据后入库；失败时孤儿内容由清理回收。
- 删除：元数据 `refcount` 减一；归零时删元数据，内容由清理异步删。
- `app.db` 用 WAL，保证并发读写。

## 5. 签名 token

独立于业务数据，存 `host.db`：

```sql
CREATE TABLE signed_tokens (
  token      TEXT PRIMARY KEY,     -- 随机 256 位，哈希后存储
  app_id     TEXT NOT NULL,
  file_id    TEXT NOT NULL,
  expires_at INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_tokens_expires ON signed_tokens(expires_at);
```

规则：
- 只回答“有效吗”：存在、未过期、app 与 file 匹配。
- 不携带身份语义，不回答“谁能看”。
- 过期即失效，定期清理。
- 存储 token 哈希，不存明文。

## 6. 宿主元数据

存 `host.db`：

```sql
CREATE TABLE apps (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  path         TEXT NOT NULL,
  manifest     BLOB NOT NULL,      -- 原始清单
  enabled      INTEGER NOT NULL DEFAULT 1,
  installed_at INTEGER NOT NULL
);

CREATE TABLE schema_migrations (
  version    INTEGER PRIMARY KEY,
  applied_at INTEGER NOT NULL
);
```

- 应用注册表由扫描目录 + 清单校验产生，落库缓存。
- 清单变更为权威；库中为派生。

## 7. 审计日志

- 结构化，按行 JSON，追加写。
- 字段：时间、app_id、subject、动作、目标、结果、错误码、耗时。
- 滚动：按大小切分，保留最近 N 份。
- 不含业务数据、不含凭据、不含文件内容。

## 8. 配额模型

| 维度 | 作用域 | 执行点 |
|---|---|---|
| KV 单值大小 | 应用 | 写入前 |
| KV 总字节 | 应用 | 写入前，累加 `kv.size` |
| 单文件大小 | 应用 | 上传流式计数，超限断开 |
| 文件总字节 | 应用 | 上传前 + 元数据累计 |
| 请求频率 | 应用 | guard 计数，滑动窗口 |

- 默认值由 config 提供，应用清单可覆盖（只能收紧）。
- 超限返回 `LIMIT_EXCEEDED`，附当前用量与上限。

## 9. 清理

| 对象 | 触发 | 策略 |
|---|---|---|
| 过期签名 token | 定时 | 删除记录 |
| 孤儿内容 | 定时 | `files/` 中存在但元数据无引用 |
| 孤儿元数据 | 定时 | 元数据存在但内容缺失（记录并标记） |
| 临时文件 | 定时 | `tmp/` 中超过 TTL 的残留 |
| 审计日志 | 滚动 | 按大小保留最近 N 份 |

- 清理按应用进行，不影响其他应用。
- 应用卸载时删除整个 `apps/<app_id>/` 目录。

## 10. 迁移

- 每个库独立版本号，存 `schema_migrations`。
- 启动时按版本顺序执行迁移，事务内完成。
- 破坏性变更需备份原库至 `apps/<app_id>/backup/`。
- 能力面稳定，数据模型可演进；API 契约不因存储变更而变。

## 11. 不变量

- 应用间无共享表、无共享目录。
- 元数据与内容分离，各自可独立恢复。
- 写入路径先校验配额，再落盘。
- 任何删除先减引用，内容延迟回收。
- 签名只证明“链接有效”，不证明“身份”。
