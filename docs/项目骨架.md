# Pegboard 项目骨架

## 1. 仓库结构

```
pegboard/
  Cargo.toml                 workspace
  crates/
    pegboard-core/           能力与治理，纯逻辑，无 HTTP
    pegboard-server/         HTTP 接入、路由、静态托管、管理页
    pegboard-cli/            单二进制入口，装配与启动
    pegboard-sdk/            前端 SDK 源码与类型产物
  apps/                      应用目录（示例与用户应用）
    ollama-chat/
    glm-quota/
    lan-share/
  docs/                      需求、架构、模块、契约、存储、SDK、骨架
  tests/                     端到端与契约测试
  scripts/                   构建、打包、示例生成
```

- workspace 统一版本与依赖。
- 能力与治理在 core，不依赖 HTTP；server 负责接入。
- 交付物为 `pegboard` 单二进制 + `apps/` + `sdk`。

## 2. Crate 划分

| crate | 职责 | 依赖 |
|---|---|---|
| pegboard-core | config、app、identity、guard、store、files、proxy、audit | 无 HTTP 框架 |
| pegboard-server | ingress、statics、admin、路由装配 | core |
| pegboard-cli | 启动、配置加载、日志、信号、打包 | server、core |
| pegboard-sdk | SDK 源码、类型、示例 | 无 Rust 依赖 |

规则：
- core 不依赖 server；server 不依赖 cli。
- sdk 独立，仅产出静态资源。
- 禁止跨层反向依赖，CI 检查。

## 3. 模块落地

core 内部模块与模块划分文档一一对应：

```
pegboard-core/src/
  config/
  app/
  identity/
  guard/
  store/
  files/
  proxy/
  audit/
```

server 内部：

```
pegboard-server/src/
  ingress/        路由、上下文、同源约束
  statics/        静态托管
  admin/          管理页与管理 API
  assets/         内嵌前端资源
```

每个模块目录含 `mod.rs` 与私有子模块；对外只暴露 `mod.rs` 中的接口。模块间通过显式接口通信，禁止深层路径互引。

## 4. 依赖方向

```
cli ──▶ server ──▶ core
                 ▲
sdk ─────────────┘（静态资源，运行时注入）
```

- 能力模块之间不互相调用；由 ingress 编排。
- guard 被能力模块调用前置于入口，不反向依赖能力模块。
- audit 为叶子，被任何模块调用。

## 5. 关键依赖选型

| 领域 | 选型 | 说明 |
|---|---|---|
| 异步运行时 | tokio | 全异步 |
| HTTP 服务 | axum | 路由与中间件 |
| 静态托管 | tower-http | ServeDir、Range、缓存 |
| HTTP 客户端 | reqwest | 代理转发 |
| WebSocket | tokio-tungstenite | WS 代理 |
| 存储 | rusqlite | 同步，WAL；每应用独立库 |
| 序列化 | serde / serde_json | 配置与 KV |
| 日志 | tracing | 结构化审计 |
| 配置 | figment 或 toml | 文件 + 环境变量 |
| CLI | clap | 启动参数 |
| 桌面壳（可选） | tauri | 非核心，可后置 |

选型冻结在 workspace 根，子 crate 不单独指定版本。

## 6. 配置

- 来源优先级：命令行 > 环境变量 > 配置文件 > 默认。
- 配置文件 `config.toml`，加载后只读。
- 敏感项（token）不进配置文件明文，走环境变量或 keyring。
- 配置结构对应 core `config` 模块，校验失败即启动失败，报明确错误。

## 7. 构建与打包

- `cargo build --release` 产出 `pegboard`。
- SDK 构建产出 `sdk.js` + `sdk.d.ts`，嵌入二进制。
- 应用目录默认 `<可执行文件同级>/apps`，可由配置覆盖。
- 打包产物：单二进制 + `apps/` + 默认 `config.toml`。
- 跨平台：Linux / macOS / Windows，CI 矩阵构建。

## 8. 测试策略

| 层 | 范围 | 方式 |
|---|---|---|
| 单元 | core 各模块 | 纯逻辑，内存存储 |
| 契约 | API 形状与错误码 | 对 server 发请求，断言响应 |
| 集成 | 能力端到端 | 起真实 server + 临时数据目录 |
| 场景 | 三个示例应用 | 浏览器侧脚本驱动 |
| 治理 | 越权、SSRF、限额 | 断言拒绝与错误码 |

- 契约测试与契约文档同步维护。
- 场景测试覆盖验收标准，作为发布门槛。

## 9. 开发约定

- 模块对外接口在 `mod.rs` 显式声明；内部实现私有。
- 错误类型统一，core 内用 `thiserror`，接入层映射为契约错误码。
- 禁止在能力模块直接写 HTTP 语义；协议转换只在 ingress。
- 所有落盘操作流式；禁止整文件入内存。
- 日志不含业务数据与凭据。

## 10. 交付与运行

- 首次运行：生成默认配置与数据目录，扫描 `apps/`。
- 运行：监听配置地址，浏览器访问 `/admin` 或应用路径。
- 停止：优雅关闭，落盘 WAL，清理临时文件。
- 升级：替换二进制即可；数据目录不变，迁移自动执行。

## 11. 边界（骨架不做）

- 无插件系统。
- 无热重载。
- 无内置应用商店。
- 无桌面壳强依赖；Tauri 可后置为可选 crate。
